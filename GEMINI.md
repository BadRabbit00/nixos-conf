# Gemini Context: NixOS "Bocchi the Rock" Configuration

This repository contains a modular NixOS configuration managed with **Flakes** and **Home Manager**, themed after the anime *Bocchi the Rock!*. It is optimized for a **Hyprland** (Wayland) desktop environment and includes specific setups for testing within a **QEMU VM** (often used under WSL2).

## Project Overview

*   **OS**: NixOS (Unstable channel).
*   **Window Manager**: Hyprland (Wayland compositor).
*   **Theme**: Catppuccin Mocha with Pink accents (#f5c2e7).
*   **Key Components**: 
    *   **Eww**: Custom status bar and widgets.
    *   **Kitty**: Primary terminal emulator.
    *   **Zsh + Starship**: Shell and prompt.
    *   **Fuzzel**: Application launcher.
    *   **SwayNC**: Notification daemon.
    *   **mpvpaper**: Animated video wallpapers.

## Project Structure

*   `flake.nix`: The entry point for the configuration. Defines inputs and `nixosConfigurations`.
*   `hosts/`: Contains host-specific configurations (e.g., `hosts/desktop/`).
    *   `default.nix`: Main host configuration, imports system modules.
    *   `hardware-configuration.nix`: Machine-specific hardware settings (autogenerated).
*   `modules/`: Reusable NixOS system modules.
    *   `core/`: Essential system services (bootloader, network, audio, user management).
    *   `hyprland/`: System-level Hyprland and Wayland support.
*   `home/`: Home Manager configuration for the user.
    *   `default.nix`: Entry point for user configuration.
    *   `desktop/`: Configuration for DE components (Hyprland, Eww, SwayNC, etc.).
    *   `programs/`, `shell/`, `terminal/`, `theme/`: Modular user-level settings.
*   `setup.sh`: A utility script to globally replace the default username (`BadRabbit`) and hostname (`badrabbitpc`) with user-defined values.

## Building and Running

### Applying Configuration
To apply the configuration to the current system:
```bash
sudo nixos-rebuild switch --flake .#<hostname>
```

### Testing in a VM (QEMU)
To build and run a virtual machine containing this configuration (useful for development in WSL2):
```bash
# Build the VM script
nix build .#nixosConfigurations.<hostname>.config.system.build.vm

# Run the VM
./result/bin/run-<hostname>-vm
```

### Initial Setup
1.  Run `./setup.sh` to set your username and hostname.
2.  Generate hardware config: `nixos-generate-config --show-hardware-config > hosts/desktop/hardware-configuration.nix`.
3.  Install: `sudo nixos-install --flake .#<hostname>`.

## Development Conventions

*   **Modularity**: Keep system-wide settings in `modules/` and user-specific settings in `home/`.
*   **Flakes Requirement**: Since this is a Flake-based project, all new files **must be tracked by Git** (`git add .`) before they can be seen by the Nix evaluator.
*   **Configuration Files**: For complex configurations (like `hyprland.conf`), use `builtins.readFile` or `home.file` / `xdg.configFile` to link external files rather than embedding long strings in Nix.
*   **Themes**: Adhere to the Catppuccin Mocha + Pink palette for consistency.
*   **Shell**: Zsh is the default user shell, managed via Home Manager.

## Key Files for Reference
*   `flake.nix`: Core dependencies and output definitions.
*   `home/desktop/hyprland/hyprland.conf`: Window manager rules and keybindings.
*   `home/desktop/eww/config/`: Layout and styling for the status bar.
*   `modules/core/user.nix`: System-level user account definition.
